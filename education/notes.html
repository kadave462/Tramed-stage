Tramed Dev Notes

Explanations of concepts learned while building the Tramed pharmacy app.

Parsing an uploaded Excel file — xlsx.read(req.file.buffer, { type: "buffer" })

This one line does a lot. Let's go piece by piece.

req.file
When the browser sends a file, multer catches it and attaches it to the request as req.file. It is an object that looks like this:

{
  fieldname: "file",
  originalname: "sales.xlsx",
  mimetype: "application/vnd.openxmlformats...",
  buffer: <Buffer 50 4b 03 04 ...>,   // ← the raw bytes
  size: 48320
}

req.file.buffer
.buffer is just one property of that object — the actual file content in raw bytes. Think of it as the file in its most raw form. Not yet readable, just a stream of numbers that represent the data.

xlsx.read()
xlsx is the library imported at the top of index.js with const xlsx = require("xlsx"). It knows how to open Excel and CSV files. xlsx.read() takes raw bytes and opens them — like double-clicking a file in Windows.

{ type: "buffer" }
This option tells xlsx: "the thing I'm giving you is raw bytes (a buffer), not a file path on disk." Without this, xlsx tries to read it as a file path and fails.

const workbook =
The result of xlsx.read() is stored in workbook. A workbook is the full opened file — it contains all the sheets inside, just like when you open an Excel file and see the sheet tabs at the bottom.

Plain English summary:

"Take the raw bytes from the uploaded file, open them with the xlsx library (treating them as a buffer), and store the result as a workbook."

The three lines that follow:

const workbook = xlsx.read(req.file.buffer, { type: "buffer" });  // open the file
const sheet = workbook.Sheets[workbook.SheetNames[0]];             // pick the first sheet
const rows = xlsx.utils.sheet_to_json(sheet);                      // turn it into an array of row objects

After these 3 lines, rows is an array you can loop through:

[
  { "INVOICE ID": 1, "PRODUCT NAME": "Paracetamol", "PRICE": 500 },
  { "INVOICE ID": 2, "PRODUCT NAME": "Amoxicillin", "PRICE": 1200 },
]

What is { type: "buffer" } and why is it needed?

What is a buffer?
A buffer is raw bytes — the file in its most primitive form. Just numbers. Like this:

<Buffer 50 4b 03 04 14 00 06 00 08 00 ...>

That is your Excel file before anything interprets it. The computer does not know yet if it is an Excel file, an image, or a video. It is just bytes.

Why { type: "buffer" }?
xlsx.read() can receive the file in different forms. It needs to know which form you are giving it:

type what you are giving xlsx
"buffer" raw bytes in memory (what multer gives us) ✓
"file" a file path like "C:/uploads/sales.xlsx"
"base64" a text string encoded as base64
"binary" a binary string

We use multer with memoryStorage() — meaning the file is never saved to disk, it lives in memory as raw bytes. So we must say "buffer".

What happens without it?

xlsx.read(req.file.buffer)  // no type option

xlsx defaults to type: "base64". It tries to read the buffer as a base64 string. The bytes don't make sense as base64, so it either throws an error or produces a corrupt empty workbook — and rows ends up empty.

Short answer:

{ type: "buffer" } tells xlsx what form the input is in so it reads it correctly.
